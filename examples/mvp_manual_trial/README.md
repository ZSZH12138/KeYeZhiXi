# MVP 人工试测材料

本目录只放**可提交的说明**。试测课包由脚本在本机生成，写入已忽略的 `runtime/`，不把真实课件、数据库、密码或 API 密钥送上 GitHub。

课包内容是为试测新写的计算机网络短笔记（IPv6 压缩、IPv4 `/24` 主机位、TCP 三次握手、吞吐量），不是某本教材的摘录。

下面可以从空目录把 GitHub `main` 上的 MVP 跑起来，并按功能点点完学生端和教师端。

## 0. 这次试测覆盖什么、不覆盖什么

覆盖（当前 MVP Web）：

- 伪匿名登录、学生选课选班、掌握画像后再组卷
- 诊断测评、随心练习、阶段评测和订正四类任务
- 选择题精确评分；填空题和主观题精确匹配或 DeepSeek 语义评分
- 订正：错因、按题订正状态，答对后退出订正、再次答错后重新进入
- 教师：班级知识地图、学生下钻、普通复核、低置信度建议复核、AI 教学建议
- 教师按课程班级配置 DeepSeek；知识处理、答疑、语义评分和教学建议使用该配置

不覆盖（本阶段明确不做）：

- 示范课包当正式课程、附录 A、多课程平台
- 图片题、分步作答、IRT 自适应生产启用
- 题目质量分析、LearningIndex
- 生产 PostgreSQL / OCR；本机试测用 SQLite

## 1. 从零准备环境

需要：Git、Anaconda/Miniconda、Python 3.11 或 3.12。

```shell
git clone https://github.com/ZSZH12138/KeYeZhiXi.git
cd KeYeZhiXi

conda create --name course-insight-framework python=3.12 -y
conda activate course-insight-framework
python -m pip install --constraint requirements/ci-constraints.txt -e ".[dev,intent]"
```

本机若已有可用的独立环境（例如此前评审用的环境），可以直接 `conda activate` 后执行同一条 `pip install`，不要往 `base` 里装包。

## 2. 生成本地试测课（不入库）

在仓库根目录：

```shell
python scripts/prepare_mvp_manual_trial.py
python manage.py migrate
python manage.py sync_roles --apply
python manage.py changepassword pseudonym_student_001
python manage.py changepassword pseudonym_teacher_001
```

`changepassword` 会在终端里让你自己设密码，不要把密码写进仓库或截图发到公开处。

若提示 `runtime snapshots already exist`，确认可以丢掉本地 `runtime/` 后再加 `--force`。`--force` 会删除整个 `runtime/`。

脚本会：

- 若还没有 `config/app.json`，从 `config/app.example.json` 复制一份（该文件被 `.gitignore`，不会提交）
- 写入 `runtime/snapshots/`、`runtime/policies/` 和旧兼容初始化所需的知识包种子
- 课程号 `course_network`，班级号 `class_01`（与 `config/roles.csv` 一致）

## 3. 启动三个进程

终端 A（网站）：

```shell
python manage.py runserver 127.0.0.1:8000
```

终端 B（事件投递；班级分析依赖它，请一直开着）：

```shell
python manage.py run_outbox_worker
```

终端 C（知识文件处理；测试“知识与题目”时请一直开着）：

```shell
python manage.py run_ingestion_worker
```

先打开 [http://127.0.0.1:8000/health/live/](http://127.0.0.1:8000/health/live/) 和 [http://127.0.0.1:8000/health/ready/](http://127.0.0.1:8000/health/ready/) ，两者都应返回健康响应。

登录页：[http://127.0.0.1:8000/accounts/login/](http://127.0.0.1:8000/accounts/login/)

需要知识抽取、题目标注、学生答疑、填空/主观题语义评分或教学建议时，登录教师后打开 `/teacher/courses/course_network/classes/class_01/deepseek/`，为精确课程和班级保存密钥；不要写入仓库。纯选择题评分不依赖它。连续登录失败 5 次会触发限流窗口（约 5 分钟）。

## 4. 试测课标准答案（学生卷上对照）

示范题库包含下列题目，实际卷面由当前任务类型和题库状态决定。

| 题意 | 正确作答 | 建议故意答错（用来测订正） |
|---|---|---|
| IPv6 里 `::` 整地址最多出现一次 | 真 / true | — |
| IPv4 `/24` 的主机位数 | `8` | `16` 或 `24` |
| 三次握手属于哪种传输层协议 | `TCP` 或 `tcp` | `UDP` |
| 8000 bit / 2 s 的吞吐量 | `4000` | `8000` |
| （备用）IPv6 允许多次 `::` | 假 / false | 真 |
| （备用）参数题「写出抽出的协议名称：{protocol}」 | 题干里**已经换成的那个词**（IPv4 / IPv6 / TCP / UDP 之一），不要填 `{protocol}` | 随便填另一个协议名 |

选择题必须完全正确才得满分。填空题和主观题若与任一标准答案完全匹配则直接得满分；不匹配时交由 DeepSeek 结合题目、来源原文和知识点评分，因此应在测试语义评分前配置课程班级密钥。

## 5. 学生端从零点一遍

用 `pseudonym_student_001` 登录。

1. 打开 `/student/`。课程填 `course_network`，班级填 `class_01`，继续。
2. 应先看到「我的掌握画像」（第一次通常是「暂无 / 证据不足」），再点「生成试卷」。
3. 页面没有自由文本任务框，直接选择 **诊断测评** 并生成试卷。
4. 记下浏览器地址里的 `assessments/<试卷号>/`，可用于核对教师复核记录。
5. **第一次建议对错混合**：锚点对、主机位错、握手填 `UDP`、吞吐量对。提交。
6. 选择题会立即规则评分；填空题和主观题在不完全匹配时进入 AI 评分。低于 0.5 的置信度应进入教师“建议复核”。
7. 打开结果页的完整反馈；每题应包含原题、选择题选项、答案、知识点、来源文件和原文，并有可自动带题目上下文跳转的答疑按钮。
8. 进入订正并对失分题作答；满分答对后，该题下次不再出现。
9. 再开一次诊断卷故意答错同一题，确认该题重新进入订正。
10. 确认本人历史只包含已完成且会改变画像的诊断测评和阶段评测；随心练习、订正和独立答疑不应改变画像统计。

退出学生账号后再测教师端（或换一个浏览器配置文件）。

## 6. 教师端从零点一遍

用 `pseudonym_teacher_001` 登录。首页 `/teacher/`。

### 6.1 班级分析

班级分析里课程 `course_network`、班级 `class_01`，打开班级。页面应有：

1. 班级知识地图
2. 学生个体（点 `pseudonym_student_001` 进入下钻）
3. 成绩复核
4. 建议复核
5. 生成 AI 教学建议

班级知识地图默认折叠，知识点显示名称和未做人数；平均掌握度与补学度不计入未做学生。学生个体下钻应能看到该生掌握、错因和按题订正状态。

学生个体栏不重复展示薄弱知识点摘要，只保留进入下钻的链接。

### 6.2 客观题标准答案

打开后给示范题增加一个可接受答案并保存，再用学生号作答验证。该配置只影响标准答案，不改当前活动知识发布版本。教师班级入口不提供“生成试卷预览”。

### 6.3 成绩复核

在普通成绩复核中输入课程、班级和学生账号，打开该生任一已完成画像测评。

- 页面逐题展示题目、答案、学生答案、得分；填空题和主观题还展示 AI 评语及教师备注。
- 每题只保留“改判”：输入不超过本题满分的分数，可附备注后确认。
- 改判后刷新学生结果、教师下钻和班级地图，确认三处同步；非满分一律按错题更新画像。

普通复核不应看到练习、订正、未完成或不改变画像的答卷。

### 6.4 建议复核

低置信度填空题或主观题会按“学生账号 + 试卷”合并为一条建议复核记录。点入只显示当前试卷待复核的题目；改判一题后仍停留在当前建议复核页，全部处理完后显示完成提示。

### 6.5 AI 教学建议

点击生成按钮，系统应使用已有人作答且班级掌握度最低的前 10 个知识点及对应来源原文生成一段建议。页面不再出现另一套确认/改写/忽略模块。

### 6.6 知识与题目及 DeepSeek

- 教师从课程进入“知识与题目”，上传一个或多个受支持的知识文件及固定格式题目 TXT，点击“确定处理”后查看真实进度、结构化知识点、题目标签和来源；当前流程没有审核编号。
- 知识抽取、题目标注和学生 RAG 答疑需要教师按课程号、班级号配置 DeepSeek；无密钥时客观测评链路仍应可跑，但答疑必须不可用。页面不得回显密钥，系统不得回退到全局或其他班级密钥。

## 7. 建议打勾清单

学生：

- [ ] 登录、选课选班
- [ ] 先画像后组卷
- [ ] 四类任务按各自规则生成
- [ ] 选择题精确评分；填空/主观题精确匹配或 AI 评分
- [ ] 本人历史只列出会改变画像的试卷，并显示试卷 ID、得分和错误情况
- [ ] 逐题反馈含原题/选项、答案、知识点、来源原文和答疑入口
- [ ] 订正答对后退出，再次画像测评答错后重新进入

教师：

- [ ] 班级地图默认折叠，名称、未做人数和平均值口径正确
- [ ] 学生下钻（掌握 / 错因 / 订正）
- [ ] 普通复核只列已完成画像测评，逐题改判与备注同步画像
- [ ] 低置信度建议复核按试卷聚合，完成后留在当前流程
- [ ] AI 教学建议使用前 10 个已作答薄弱知识点及来源原文
- [ ] 知识与题目：上传、确定处理、进度、知识点/题目来源
- [ ] DeepSeek 配置页不回显密钥

## 8. 常见卡住

- 班级地图一直空：确认 Worker 在跑，并至少有一次已完成的学生提交。
- `COURSE_ARTIFACT_INVALID`：不要手改课包换行；用脚本重生（`--force`）。
- 跟练提交后订正状态不变：必须从**失分题**点「开始本题跟练」，做对后再打开原来的结果/订正页。
- 参数题总是错：抄题干里已经替换出来的协议名，不要填花括号模板。
- 登录被拒：账号必须是 `pseudonym_student_001` / `pseudonym_teacher_001`，且已 `sync_roles --apply`。
