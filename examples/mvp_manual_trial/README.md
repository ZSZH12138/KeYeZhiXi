# MVP 人工试测材料

本目录只放**可提交的说明**。试测课包由脚本在本机生成，写入已忽略的 `runtime/`，不把真实课件、数据库、密码或 API 密钥送上 GitHub。

课包内容是为试测新写的计算机网络短笔记（IPv6 压缩、IPv4 `/24` 主机位、TCP 三次握手、吞吐量），不是某本教材的摘录。

下面可以从空目录把 GitHub `main` 上的 MVP 跑起来，并按功能点点完学生端和教师端。

## 0. 这次试测覆盖什么、不覆盖什么

覆盖（当前 MVP Web）：

- 伪匿名登录、学生选课选班、掌握画像后再组卷
- 四段诊断卷（公共锚点 / 不确定点 / 误区 / 补救）
- 客观题规则评分、多可接受答案、参数题干冻结
- 测后订正：错因、一层最小提示、按题跟练、按题订正状态
- 教师：客观题答案、四段蓝图（不改已审核知识包）、班级五个入口、学生下钻、成绩复核/改判/驳回、教学建议确认/改写/忽略
- 可选：教师页配置 DeepSeek；客观题路径不依赖它

不覆盖（本阶段明确不做）：

- 示范课包当正式课程、附录 A、多课程平台
- 图片题、分步作答、IRT 自适应生产启用
- 题目质量分析、LearningIndex
- 生产 PostgreSQL / OCR；本机试测用 SQLite

## 1. 从零准备环境

需要：Git、Anaconda/Miniconda、Python 3.11 或 3.12。

```shell
git clone https://github.com/ZSZH12138/KeYeZhiXi.git
cd KeYeZhiXi

conda create --name course-insight-framework python=3.12 -y
conda activate course-insight-framework
python -m pip install --constraint requirements/ci-constraints.txt -e ".[dev,intent]"
```

本机若已有可用的独立环境（例如此前评审用的环境），可以直接 `conda activate` 后执行同一条 `pip install`，不要往 `base` 里装包。

## 2. 生成本地试测课（不入库）

在仓库根目录：

```shell
python scripts/prepare_mvp_manual_trial.py
python manage.py migrate
python manage.py sync_roles --apply
python manage.py changepassword pseudonym_student_001
python manage.py changepassword pseudonym_teacher_001
```

`changepassword` 会在终端里让你自己设密码，不要把密码写进仓库或截图发到公开处。

若提示 `runtime snapshots already exist`，确认可以丢掉本地 `runtime/` 后再加 `--force`。`--force` 会删除整个 `runtime/`。

脚本会：

- 若还没有 `config/app.json`，从 `config/app.example.json` 复制一份（该文件被 `.gitignore`，不会提交）
- 写入 `runtime/snapshots/`、`runtime/policies/` 和知识包种子
- 课程号 `course_network`，班级号 `class_01`（与 `config/roles.csv` 一致）

## 3. 启动两个进程

终端 A（网站）：

```shell
python manage.py runserver 127.0.0.1:8000
```

终端 B（事件投递；班级分析依赖它，请一直开着）：

```shell
python manage.py run_outbox_worker
```

先打开 [http://127.0.0.1:8000/health/live/](http://127.0.0.1:8000/health/live/) 和 [http://127.0.0.1:8000/health/ready/](http://127.0.0.1:8000/health/ready/) ，两者都应返回健康响应。

登录页：[http://127.0.0.1:8000/accounts/login/](http://127.0.0.1:8000/accounts/login/)

DeepSeek 可选。密钥只放本机环境变量 `DEEPSEEK_API_KEY`，或登录教师后打开 `/teacher/deepseek/`。不要写入仓库。客观题试测不需要它。连续登录失败 5 次会触发限流窗口（约 5 分钟）。

## 4. 试测课标准答案（学生卷上对照）

默认诊断蓝图四段各 1 题，总分 4。题库里还有两道备用题，给教师改蓝图或参数题预览用。

| 题意 | 正确作答 | 建议故意答错（用来测订正） |
|---|---|---|
| IPv6 里 `::` 整地址最多出现一次 | 真 / true | — |
| IPv4 `/24` 的主机位数 | `8` | `16` 或 `24` |
| 三次握手属于哪种传输层协议 | `TCP` 或 `tcp` | `UDP` |
| 8000 bit / 2 s 的吞吐量 | `4000` | `8000` |
| （备用）IPv6 允许多次 `::` | 假 / false | 真 |
| （备用）参数题「写出抽出的协议名称：{protocol}」 | 题干里**已经换成的那个词**（IPv4 / IPv6 / TCP / UDP 之一），不要填 `{protocol}` | 随便填另一个协议名 |

判断题页面一般是「对 / 错」。填空只比去掉首尾空白，**大小写和内部空格按原样**；所以 `TCP` 和 `tcp` 都算对，但 ` Tcp ` 去空白后是 `Tcp`，不算对，除非教师在「客观题标准答案」里另加一行。

## 5. 学生端从零点一遍

用 `pseudonym_student_001` 登录。

1. 打开 `/student/`。课程填 `course_network`，班级填 `class_01`，继续。
2. 应先看到「我的掌握画像」（第一次通常是「暂无 / 证据不足」），再点「生成试卷」。
3. 「学生任务说明」任意写一句非空中文（例如「我要做诊断测评」）。任务类型选 **诊断测评**。
4. 当前试卷应出现 **四段标题**，用途分别为 `anchor` / `uncertainty` / `misconception` / `remediation`（页面上会显示中文段名）。记下浏览器地址里的 `assessments/<试卷号>/`，教师复核要用这个试卷号。
5. **第一次建议对错混合**：锚点对、主机位错、握手填 `UDP`、吞吐量对。提交。
6. 本试测课全是客观题，规则分是 `not_required`，提交后应能直接看到得分，**不应**把待复核分当成最终成绩展示。若出现「成绩正在复核中」，先不要当最终分，去教师端确认或驳回后再回来刷新。
7. 打开结果页的安全反馈、完整反馈（证据引用、按题订正状态）。
8. 进入测后订正：先看错因；再点「展开一层提示」（只应多一层，不应直接给最终答案）；对每道失分题点「开始本题跟练」。
9. 跟练是新的一张单题卷。用正确答案提交。回到原结果/订正页，该题订正状态应变为已订正一类文案，而不是只看班级掌握度。
10. 再开一次诊断卷（或练习），这次可以全对，确认画像/进步轨迹在教师确认后的后续测评里会变化。第一次提交后画像可能仍空，直到学习事件被 Worker 投递、且教师侧完成必要确认。

退出学生账号后再测教师端（或换一个浏览器配置文件）。

## 6. 教师端从零点一遍

用 `pseudonym_teacher_001` 登录。首页 `/teacher/`。

### 6.1 班级五个入口

班级分析里课程 `course_network`、班级 `class_01`，打开班级。页面应有：

1. 班级知识地图
2. 误区
3. 学生个体（点 `pseudonym_student_001` 进入下钻）
4. 复核
5. 教学建议

学生个体下钻应能看到该生掌握、错因、按题订正状态（学生打开过订正后才有记录）。

班级页还有「编辑客观题标准答案」和「配置四段诊断卷」。

### 6.2 客观题标准答案

打开后给 `item_transport_handshake` 增加一行 `Tcp`（单独一行）。保存。用学生号再答一题填 `Tcp`，应判对。这只改运行配置，不应改已审核知识包 CAS。

### 6.3 四段诊断卷

打开「配置四段诊断卷」：

- 四段用途应能改成锚点 / 不确定点 / 误区 / 补救
- 可改题量、分数、锚点题号（例如某段锚点改成 `item_ipv6_follow` 或加上 `item_protocol_template`）
- 保存后应出现「发布前预览」，参数题干里的 `{protocol}` 应已换成具体词
- 保存后学生新生成的卷应跟新蓝图走；**不要**去改 `runtime` 里已发布知识包 JSON 来“调题”

题量大于题库能满足的约束时，预览会暂时不可用，把题量改回 1 再保存即可。

### 6.4 成绩复核 / 改判 / 驳回

在班级「复核」或教师首页「成绩复核」填入第 5 步记下的试卷号。

- **确认**：维持规则分
- **改分**：把对改成错或把错改成对，只影响这份答卷
- **驳回**：学生结果应变为「成绩正在复核中，暂不公布最终得分」，在重评完成前不得把驳回分当最终成绩

改分后刷新学生结果、教师下钻和班级地图，确认跟这份答卷一致。

### 6.5 教学建议

若班级页出现候选建议，分别试一次 **确认 / 改写 / 忽略**。确认只表示采纳候选，不等于已经上过那堂课。

### 6.6 知识包审核与 DeepSeek

- 「知识包审核」需要审核编号。本试测脚本走的是本地离线发布，页面上可能没有待审编号，空着或查不到属于预期，不必强行当成失败。
- DeepSeek：无密钥时客观链路仍应可跑。有密钥时只通过环境变量或教师配置页填写，页面不得回显密钥。

## 8. 常见卡住

- 班级地图一直空：确认 Worker 在跑，并至少有一次已完成的学生提交。
- `COURSE_ARTIFACT_INVALID`：不要手改课包换行；用脚本重生（`--force`）。
- 跟练提交后订正状态不变：必须从**失分题**点「开始本题跟练」，做对后再打开原来的结果/订正页。
- 参数题总是错：抄题干里已经替换出来的协议名，不要填花括号模板。
- 登录被拒：账号必须是 `pseudonym_student_001` / `pseudonym_teacher_001`，且已 `sync_roles --apply`。
