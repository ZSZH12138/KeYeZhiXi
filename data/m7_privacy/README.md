# M7 隐私复核数据与模型工件

本目录只保存数据清单、许可与来源说明，以及团队自行编写或生成的小型合成测试夹具。不要提交真实学生答案、个人信息、完整外部数据集或训练后的 `joblib` 文件。

## 数据准入

训练数据必须先填写 `manifest.example.json` 中的全部字段，并把文件改成与数据版本一一对应的清单。`model-manifest.example.json` 是另一份仅用于运行时模型工件的模板，二者不能混用。以下任一情况不得进入生产训练：

- `license_spdx` 为 `NOASSERTION`；
- 禁止商业使用、禁止再分发，或项目未取得所需书面授权；
- 来源、不可变版本或 SHA-256 不可验证；
- 含真实学生或未取得有效授权的个人信息；
- `approval_status` 不是 `approved`。

仓库内测试样本应当是项目成员从零编写的合成句子，并避免使用真实姓名、电话、住址和证件号。外部数据仅在获准的隔离训练环境中按不可变版本下载，不能由应用运行时自动下载。

## 分类标签

语义分类器固定使用以下顺序，训练、工件清单和运行时必须完全一致：

1. `SAFE`
2. `SELF_ADDRESS`
3. `SELF_FAMILY`
4. `SELF_HEALTH`
5. `SELF_IDENTITY`

数据切分应按模板或释义组隔离，避免同一模板的轻微改写同时出现在训练集和测试集。离线报告至少包含高风险个人信息召回率、正常答案误拦率、进入人工复核的比例及置信区间，并包含普通课程日期、数学日期、课程组织名等硬负例，以及 NRP、出生日期和就读/任职组织等敏感或自述正例。仅使用合成数据的结果不能直接批准生产放行。

## 模型工件

运行时目录中的模型子目录必须由可信管理员部署，结构如下：

```text
privacy-model/
  manifest.json
  model.joblib
```

`manifest.json` 必须符合 `privacy_reviewer.py` 的严格字段要求，结构可从 `model-manifest.example.json` 开始填写。它包含固定标签、归一化版本、数据集 SHA-256、模型 SHA-256、组件类型、依赖版本、带时区的生成时间和训练来源。应用配置必须在工件之外单独钉住模型 ID、版本、模型 SHA-256 和 manifest SHA-256；manifest 的 Python、scikit-learn、joblib 版本必须与运行时完全相同，且所有比对在反序列化前完成。

`joblib` 反序列化能够执行代码，因此即使双 SHA-256 与版本校验通过，也只允许加载可信管理员控制的本地工件；绝不能加载上传文件、请求参数指定的路径或未经审批的数据产物。SHA-256 是一致性钉住，不是发布者签名；部署权限和运行目录仍须隔离。

## 运行原则

Presidio、中文 spaCy 模型、scikit-learn 或工件任一缺失、版本不符、校验失败、执行异常或置信度不足时，复核结果必须是 `review`，不得回退为“关键词检查通过后直接外发”。只有所有启用的本地复核器都返回 `allow`，上层才可以继续调用远端模型。

真实 Presidio + `zh_core_web_sm` 仅批准部署在 Python 3.11–3.13。目标环境必须显式
设置 `M7_PRESIDIO_ZH_SMOKE=1` 并运行
`tests/integration/test_m7_privacy_runtime_smoke.py`；普通 CI 中的跳过结果和 Python
3.14 下的假 analyzer/fail-closed 单测都不代表真实中文链路已跑通。
