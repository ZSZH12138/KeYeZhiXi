# Windows 桌面版

本文定义课业智析 Windows 本地应用的运行边界、首次初始化、进程生命周期、打包方式与验收标准。桌面层只负责启动和管理现有 Django 平台及两个 Worker，不改变管理员、教师、学生页面，也不改变 M0–M9 的业务边界。

## 交付形式

桌面版采用 PyInstaller `onedir` 文件夹模式，交付目录包含一个用户可见入口和内部依赖目录：

```text
KeYeZhiXi/
├── KeYeZhiXi.exe
└── _internal/
```

目标电脑不需要安装 Python、Conda 或项目依赖。程序文件保持只读，账号、数据库、上传资料、模型配置和日志不进入安装目录。

## 组件与生命周期

用户双击 `KeYeZhiXi.exe` 后，桌面主进程显示状态窗口，并以同一个 EXE 的内部服务模式启动三个独立子进程：

1. Django Web 平台；
2. 知识解析 Worker；
3. 事件投递 Worker。

主进程取得 Windows 单实例锁，准备本地配置，执行数据库迁移，再启动三个服务。Web 平台只监听 `127.0.0.1:8000`。主进程必须等 `/health/ready/` 返回就绪后，才打开 `http://127.0.0.1:8000/accounts/login/`。

状态窗口展示三个服务的状态，并提供“打开登录页”“重新启动平台”和“停止平台”。关闭状态窗口等同于停止平台：主进程先请求子进程正常退出，超时后再强制回收，最后释放单实例锁。

任一核心子进程异常退出时，主进程停止其余进程并报告日志位置，不让缺少 Worker 的平台继续运行，也不进行无限自动重启。

## 持久数据

桌面版固定使用当前 Windows 用户的本地应用数据目录：

```text
%LOCALAPPDATA%\KeYeZhiXi\
├── config\
├── runtime\
├── logs\
└── .env
```

该目录在替换、移动或升级程序文件夹后保持不变。关闭应用不会删除其中的数据。应用不能要求管理员权限，也不能把运行数据回退到程序目录。

首次启动从安装包复制无密钥配置模板，并生成本机独立的 Django 安全密钥。`.env`、数据库、业务资料、日志和 DeepSeek 密钥都不得进入构建产物或 Git。

## 首个管理员

迁移完成后，只有在数据库中完全没有账户时，启动器才显示一次性的首个管理员窗口。管理员输入账户名、密码和确认密码；账户名和密码只要求不为空或全为空白。

创建流程复用现有 `system_admin` 角色、权限组和角色同步逻辑，内部生成匿名化 actor ID，并用 Django 密码哈希保存密码。账户名和密码不得进入日志或子进程参数。角色创建、账户名设置和密码设置必须处于同一数据库事务内；失败时不得留下不可登录的半成品账户。

一旦数据库出现账户，首次管理员入口必须关闭。教师和学生账户继续只能由管理员在现有 Web 页面创建和物理注销。

## 故障处理

- 重复启动：不创建第二套服务；提示应用已经运行并打开现有登录页。
- 8000 端口冲突：不改用其他端口，不启动 Workers，不打开浏览器，并明确报告冲突。
- 配置损坏、目录不可写、迁移失败、管理员初始化失败、服务启动失败或健康检查超时：停止已经启动的进程，显示简明原因和日志目录。
- 浏览器打开失败：平台继续运行，用户可通过状态窗口再次打开登录页。
- Worker 锁冲突或数据库错误：停止整套服务，避免不完整运行。

## 安全边界

- Web 平台仅绑定本机回环地址；
- 每个本地安装生成独立随机安全密钥；
- 子进程使用参数列表且不通过 Shell 拼接；
- 本地首次管理员窗口不增加临时 Web 注册接口；
- 明文账户密码和 DeepSeek 密钥不得写入日志、配置模板或命令行；
- 教师、学生和管理员的现有授权规则保持不变；
- 程序不内置默认账户、默认密码或测试数据。

## 实现边界

桌面代码放在 `src/course_insight/desktop/`，按路径配置、首次初始化、进程监管、界面和入口分离。PyInstaller 规格放在 `packaging/`，Windows 构建脚本放在 `scripts/`。Django 设置只增加显式桌面数据根目录支持，不把桌面生命周期逻辑放入 `AppConfig.ready()` 或 Web 请求。

打包时必须显式包含 Django 模板、迁移、项目动态模块、Tkinter、SQLite 和无密钥配置模板。不得包含本地数据库、账号、课程资料、题库、知识点、日志、`.env`、API 密钥、Git 数据或测试缓存。

当前 `course-insight` Conda 环境不因打包而安装额外依赖。构建工具安装到被 Git 忽略的隔离目录，构建完成后仅保留 `dist` 交付物。

## 验证标准

实现采用测试先行，并至少验证：

1. 路径解析、单实例、服务命令、健康检查、浏览器时序和子进程回收的单元测试；
2. 临时本地数据目录中的配置初始化、数据库迁移、首个管理员权限和二次启动行为；
3. 实际 EXE 在不依赖外部 Python 的情况下启动登录页和两个 Worker；
4. 关闭状态窗口后没有应用子进程残留；
5. 替换程序目录后继续使用原本地数据；
6. 现有完整测试集继续通过；
7. 新增桌面模块测试覆盖率不低于 80%。

## 非目标

本次不增加 Windows 系统服务、开机自启动、自动更新、MSI 安装器、局域网访问、云端部署或默认管理员密码。
