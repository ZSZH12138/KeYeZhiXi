# M7/M9 修复的跨模块变更请求与影响说明

状态：随 M7/M9 修复 Draft PR 提交，等待负责人及全局审核 Codex 判定。

目的：本文不是单方面修改既有协议，也不假定 M2/M8 必须接受新职责。本文把修复
过程中发现的跨模块影响、当前可在模块内部完成的工作和可能需要模块负责人另行处理
的事项分开列出，请全局审核 Codex 对照现有权威协议判断：

1. 当前修复是否符合既有契约；
2. 是否存在职责跨界；
3. 是否需要拆分并向 M2 或 M8 负责人创建独立任务；
4. 是否应调整本 PR 的实现范围。

配套产品决定见 `docs/m7_m9_remediation_decisions.md`。

## 1. M2 影响判定

### CR-M2-01：当前 locator-only 学生引用

当前修复决定为：学生页面暂时只显示已有引用的 `source_id` 与 `locator`，不显示
`EvidenceChunk.text`。

初步判断：**本轮不要求修改 M2 契约或实现。** M7 可以使用现有 EvidenceBundle
字段构造不含原文的学生引用，M0 页面只呈现来源定位。

请全局审核 Codex 确认：

- 现有 M2/M7 接口是否允许 M7 不向学生返回 `EvidenceChunk.text`；
- 公共 v1 的 `EvidenceCitation.quote: str` 保持必填；M7 只写精确的安全占位值，
  SQLite/PostgreSQL 读回和导入把受支持的旧 quote 形状规范化为同一占位值，M0
  locator-only 视图不显示它；
- 当前只认可 M1 的 `paragraph:<正整数>` 与仓库已有数字型 `section`/`p.` legacy
  格式；其他 locator 在结构化 typed locator v2 发布前失败关闭；
- 如果公共契约不能在本 PR 中改变，是否应由 M7/M0 通过专用学生视图模型隐藏原文。

### CR-M2-02：未来恢复安全短摘录（非本轮阻断项）

未来若要求学生看到证据短摘录，可能需要为课程证据提供机器可验证的可见性信息，
例如：

- 是否允许学生查看；
- 内容类别是否为答案、评分规则、教师专用材料或普通课程材料；
- 可展示摘录的边界或经过审核的 excerpt。

初步判断：这可能属于 M2 证据治理职责，但**当前 locator-only 修复不依赖它**。

请全局审核 Codex 判断是否需要向 M2 负责人创建后续任务；在得到明确结论前，本 PR
不得自行扩展 M2 公共契约。

## 2. M8 影响判定

### CR-M8-01：`reject` 的权威业务语义

负责人确认的产品语义为：`reject` 表示拒绝本次评分，等待重新评分或教师提交完整
`override`；不得自动记零分，被拒绝分数不得更新 M5 状态或进入 M9 分数统计。

现有代码链路中：

- M9 产生并持久化 `TeacherReviewDecision`；
- M8 `apply_teacher_review(...)` 消费该决定；
- 应用工作流随后把结果送入 M5，并重新生成 M9 分析；
- 当前 `reject` 会形成 `review_status="rejected"` 的新审计版本，但流程仍继续消费其
  分数，因而与上述产品语义不一致。

初步判断：完整修复不可只改 M9 的局部校验，必须统一 M9、M8、应用工作流、M5 和
M9 报表行为。因此该项存在实际跨模块影响。

### 当前 Draft 候选的已知阻断缺口

当前候选实现已经做到：M8 把驳回版本标为 `rejected_pending_rescore`，M5 拒绝再次
消费该 rejected bundle，M9 分数统计和学生页面隐藏该分数，应用复核路径也不会再
用驳回版本追加一次 M5 更新。

公共 v1 的 `IndividualReport.recent_score` 已恢复为非 nullable；rejected 报告省略
个人报告，并用 M9 私有 learner-scope tombstone 阻止查询回退旧报告。曾写入
`recent_score=null` 的实现只存在于未合并草稿，确认没有生产数据，因此不做会改写
报告/审计校验和的生产迁移；本地草稿库必须隔离重建，读回和导入失败关闭。

但这**还不等于完整清除 M5 影响**。现有 `submit_assessment(...)` 在教师作出决定前
已经无条件用初始模型评分更新 M5，并让 M6/M9 消费该状态；复核时仅复用该状态，
因此原评分对 mastery、班级聚合和后续状态的影响仍然存在。只断言“reject 后没有
新增 state version”不能证明状态已经净化。本 Draft PR 不应把这一候选描述为完整
落地的方案 A。

要闭合该缺口，至少需要全局审核在下列方向中选择并冻结协议：

1. 由 M5 使用提交工作流已冻结的 pre-score learner/class baseline，原子追加一个
   补偿/重建版本；或
2. 调整整体工作流，使所有 `teacher_review_required` 初始评分在 confirm/override
   前都不进入 M5/M6/M9。

同时，当前 M8/应用公开流程没有可到达的“重新评分”入口：已有 rejected record
只能继续由完整 `override` 覆盖，且同一 paper/attempt 的提交幂等约束不允许把普通
再次提交当作重评。全局审核必须明确冻结 rescore 的身份、版本、触发权限、与原
attempt 的关联、幂等及恢复协议；否则学生页“等待重新评分”的文案只能表示未来
状态，不能宣称该路径现已可用。

若选择补偿协议，还必须定义：

- legacy run 没有冻结基线时失败关闭；
- 基线已不连续或拒绝期间出现并发新状态时失败关闭；
- 首次评估没有历史基线时使用明确的“无证据状态”，不能用零分伪装；
- 空诊断、已处理审计水位、补偿版本身份、幂等重放和崩溃恢复语义；
- 已经由初始评分触发的 M6 教学动作与学生反馈如何废止、隐藏或重建；reject 后
  override/rescore 必须生成与新权威评分一致的反馈，不能继续复用 submit 阶段的
  `feedback_id`；
- 验收测试直接比较 learner mastery、class aggregate 和审计水位是否恢复，而不只
  比较 state version 数量。

请全局审核 Codex 对照既有协议明确：

1. 既有协议是否已经定义了 `reject` 的不同语义；
2. 如果既有协议与负责人本次确认冲突，应以哪一份权威决定为准；
3. 本 PR 是否可以直接修改 M8/应用/M5/M9 的消费路径；
4. 或者是否应保留本 PR 的 M9 校验修复，并向 M8 负责人拆出独立阻断任务；
5. 是否需要新增明确状态（如 `rejected_pending_rescore`）或新的领域事件/工作流终态，
   而不是复用含义模糊的 `rejected`。
6. M5 补偿/重建协议由 M5 负责人、M8 负责人还是应用工作流负责人主责，是否应把
   本 Draft 中未闭合的 reject 候选拆出并阻断合并。

在审核结论产生前，Draft PR 中相关实现应被视为“待协议复核的候选实现”，不得在
PR 描述中宣称已经代表全部模块负责人达成新协议。

### CR-M8-02：M9 模型质量报告（非本轮实现项）

M9-05 需要 M8 提供真实 shadow 标定结果、样本量、指标、模型/参数版本和数据水位。
当前 M8 返回零样本空标定，M9 返回 `insufficient_data` 与现有边界一致。

初步判断：本轮不应修改或伪造该能力。请全局审核 Codex 判断何时向 M8 负责人创建
真实标定任务；在该任务完成前，M9-05 保持暂缓。

## 3. 不建议跨模块转移的职责

以下事项初步仍属于 M7 自身职责，不建议因为调用 M2/M8 数据而转移给其他模块：

- 学生可见输出的最终安全门；
- 调用 DeepSeek 前的学生答案个人信息出站治理；
- 所有 M7 评分结果强制进入教师复核；
- M7 模型调用的隐私最小化审计与保留策略。

请全局审核 Codex 如认为上述归属与现有协议不符，在审核意见中引用对应协议位置并
提出具体拆分建议。

### 仍需 M0/全局安全边界判定

- 当前审计读取服务以 `requester_role="system_admin"` 执行模块内失败关闭，但尚无
  Web 读取入口。若未来开放读取，应由 M0 从已认证 `ActorContext`/有效 grant 推导
  角色，不能信任调用者提交的裸字符串；请判定是否现在拆出 M0 RBAC 任务。
- 当前学生 locator-only 视图不显示 `EvidenceChunk.text`，但 `source_id`/`locator`
  仍是公共契约自由字符串；任意上游数据是否保证它们只含定位元数据，需要 M2/全局
  契约所有者确认。
- M7 审计和 M9 一样使用普通 SHA-256，仅防程序错误、误关联和迁移损坏，不抵抗能
  同时改写 payload 与 checksum 的数据库高权限主体。
- 旧 SQLite `m7_student_feedback` 表没有独立 payload checksum；导入可以拒绝非法、
  混合或身份不一致的形状，却无法识别“被改成另一份仍完全合法 payload”的历史
  改写。全局审核应判断这是否仍在当前一致性目标内，或需要新迁移补 checksum。
