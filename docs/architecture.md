# 课业智析架构说明

本文是当前 MVP 的权威架构说明。历史设计、阶段计划和人工试验记录不属于发布文档。

## 1. 总体结构

课业智析是一个 Django 外层驱动的模块化单体：

```text
浏览器
  │
  ▼
M0 Django：登录、权限、账户、课程班级页面、Worker 命令
  │
  ▼
Application：跨模块用例、幂等、恢复、事务边界
  │
  ├── M1 课程治理 ── M2 证据检索 ── M3 知识与题库
  ├── M4 任务编排 ── M8 测评评分 ── M5 学习状态
  └── M6 辅导控制 ── M7 DeepSeek ── M9 教师分析
  │
  ▼
SQLite（本地）或 PostgreSQL + pgvector（生产）
```

M1–M9 不依赖 Django Request、ORM 对象或模板。跨模块数据使用 `src/course_insight/contracts/` 中的 Pydantic 契约传递，跨模块用例由 `AppCoordinator` 和应用层服务编排。

## 2. 账户与权限

平台只有三种全局账户类型：管理员、教师、学生。服务端同时检查账户类型、Django 权限和课程班级作用域，页面隐藏不是授权手段。

| 账户 | 允许操作 | 禁止操作 |
|---|---|---|
| 管理员 | 创建/物理注销教师和学生账户 | 管理课程、班级、成员和教学内容 |
| 教师 | 创建班级、邀请/移出学生、管理本班内容与分析 | 创建/注销账户，进入其他教师班级 |
| 学生 | 进入本人班级，测评、订正、查看本人记录和答疑 | 管理账户、班级、成员或他人数据 |

外部登录名与内部业务身份分离：

- `username` 是用户输入的账户名，只要求非空且不能全为空白；
- `actor_id` 是创建账户时生成的不可变伪匿名 ID，供契约、学习记录和模块表使用；
- `username_digest` 用于不区分数据库后端的唯一性检查；
- 密码使用 Django Password Hasher 保存，不保存明文。

教师和学生只能由管理员页面创建。`roles.csv` 只负责首次管理员引导和管理员权限恢复，不创建或复活教师、学生。

## 3. 账户物理注销

账户注销是单次事务内的物理清除，不保留“已删除账户名”黑名单，因此旧账户名可再次注册为新的独立账户。

学生注销流程：

1. 锁定目标用户并再次核对账户类型和确认账户名；
2. 删除 M0、M4–M9 中引用该内部 `actor_id` 的会话、作答、评分、反馈、画像和分析数据；
3. 删除班级成员关系、Django 会话和身份投影；
4. 更新受影响班级的名单版本和统计；
5. 删除用户行。

教师注销流程：

1. 锁定目标用户并核对确认值；
2. 对教师拥有的每个课程班级执行精确 `(course_id, class_id)` 清除；
3. 删除该范围的成员关系、授权、知识入库任务、课程文件版本、知识发布版本、题库、知识点、模型密钥、学习数据和冻结提交文件；
4. 删除班级容器和教师用户行；
5. 事务提交后清理文件系统中的上传物与冻结答卷。

数据库清除失败时事务回滚，不能留下“用户已删、课程未删”的半完成状态。文件删除采用事务提交后的待办队列，可用 `python manage.py cleanup_erasure_files` 重试。生命周期记录只在目标用户仍存在时保留失败信息；成功删除后会随用户级联清除，不保存账户名或可用于阻止复用的指纹。

SQLite 的低层清除使用固定表白名单和参数化条件；不会按任意表名或字符串拼接执行删除。PostgreSQL 上的教师班级级联清除需要部署对应的受控适配器；缺失时失败关闭。

## 4. 课程与班级

教师在登录后的课程班级页创建独立容器，并填写课程名称和班级名称。系统同时生成不可变 `course_id` 与 `class_id`：显示名称可以对人友好，内部 ID 用于授权、幂等和历史引用。

教师首页从 `CourseClassWorkspace` 读取该教师实际拥有的全部活动班级，而不是只显示当前会话刚创建的班级。旧工作区若没有显示名称，会通过迁移或运行时标签函数得到稳定的可读名称。

班级成员以 `ClassMembership` 为权威来源。邀请或移出学生后：

- 名单版本递增；
- 学生课程列表立即变化；
- M5/M9 班级快照按当前有效成员修复；
- 学生总数、已做人数和未做人数重新计算。

管理员没有班级操作权限。

## 5. 知识入库与发布

教师对一个精确课程班级上传课程资料或题目文件，确认后创建 `KnowledgeIngestionJob`。独立 ingestion Worker 完成：

1. 文件格式、大小、容器和来源校验；
2. M1 确定性解析与分块；
3. M7 DeepSeek 多知识点抽取；
4. M3 概念合并、题目解析与多知识点关联；
5. M2 证据索引构建；
6. 发布校验；
7. 原子切换活动 `CourseKnowledgeRelease`。

新增和删除只影响后续活动版本。已经生成的试卷继续引用其冻结版本，不被后来发布反向修改。知识文件、题目和 DeepSeek 配置都按课程班级隔离。

## 6. 学习与评分闭环

学生只能选择四类测评任务：

- 诊断测评：更新个人与班级画像；
- 随心练习：即时练习，不进入画像历史；
- 阶段评测：更新个人与班级画像；
- 错题订正：处理错题，不进入画像历史。

选择题按冻结答案精确评分。填空题和主观题在精确匹配失败时进入 M7 的受约束语义评分；低置信度或模型失败题进入教师建议复核。教师改判生成新的追加式审计版本，并同步学生反馈、M5 画像和 M9 班级统计。

诊断和阶段评测开始时冻结当时的成员规模与名单校验和。班级知识地图只用实际做过对应知识点的学生计算平均掌握度；无人作答时显示 0，不用缺失数据伪造统计。

## 7. 答疑与来源

学生答疑先从当前活动发布版本检索课程原文，再由 M7 生成答案。页面展示来源文件、页码/幻灯片/行号和短引文。逐题答疑使用短时签名引用，服务端重新校验学生、课程、班级、试卷和题目，浏览器不能通过修改字段读取其他范围的数据。

每个班级使用教师单独保存的 DeepSeek 密钥。缺少密钥时失败关闭，不读取其他班级或全局密钥。课程材料不足而允许外部检索时，页面必须区分课程来源与外部来源并提示核对事实。

## 8. 持久化与进程

平台有三个独立进程角色：

- Web：页面、鉴权、同步业务请求和健康检查；
- ingestion Worker：知识文件解析、模型抽取和原子发布；
- outbox Worker：学习事件的 at-least-once 投递。

`runtime/` 保存部署实例的数据、上传文件、日志、Worker 状态和本地模型制品，全部被 Git 忽略。可提交目录不保存账户、作答、课程资料、密钥或运行数据库。

SQLite 是本地与离线基线；生产使用 PostgreSQL + pgvector。两种后端遵守相同契约、作用域、版本、checksum 和幂等规则，但不双写。

## 9. 不变量

- 账户类型和课程班级作用域必须在服务端校验；
- 管理员只管理账户，教师只管理本人班级，学生只访问本人数据；
- 账户名与内部 `actor_id` 分离，物理注销后账户名可复用；
- 教师注销必须同时清除其拥有的全部班级及班级数据；
- 模块只访问自身持久化前缀，不跨模块直接读业务表；
- 历史试卷、评分审计和发布引用是追加式或冻结的；
- 密钥、原始作答和完整提示词不得进入日志或 Git；
- 外部模型、向量数据库或隐私工件不可用时明确失败或降级，不能伪造成功。

公开契约生产者与消费者的机器可检验映射见 [`contracts/contract_provenance.json`](../contracts/contract_provenance.json)。
