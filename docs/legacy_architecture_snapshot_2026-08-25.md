# 课业智析旧架构历史快照（M0–M9）

> 快照日期：2026-08-25
> 文档性质：历史事实记录，不再作为后续功能实现规范。
> 后续规范：以 [`knowledge_ingestion_rag_redesign.md`](knowledge_ingestion_rag_redesign.md) 为准。

## 1. 快照目的

本文件在知识入库与学生答疑架构重构前，冻结项目当时的模块边界、关键流程、可复用资产和已知问题。重构应覆盖不再适用的实现，但不能无意破坏仍有价值的 M0–M9 能力。

本快照依据以下项目材料与代码现状整理：

- 根目录 `README.md`、`docs/architecture.md` 及 `docs/` 中现有说明；
- M0–M9 各模块 `README.md`；
- `D:/课业智析_项目计划书.md`；
- Django 路由、教师端页面、运行时装配、M1–M3 服务和 M0 Worker 实现；
- 2026-08-24 至 2026-08-25 的人工测试与故障诊断记录。

## 2. 总体架构事实

旧系统是 Python 模块化单体，继续使用 M0–M9，不存在 M10：

- Django Web、认证授权、运行时、健康检查和后台 Worker 属于 M0；
- 模块间通过 Pydantic 公共契约交换数据；
- `AppCoordinator` 负责跨模块编排，不应越过服务直接读取其他模块私有表；
- PostgreSQL 是生产目标数据库；M2 在生产模式使用 PostgreSQL 与 pgvector；
- SQLite 和内存仓库主要用于本地测试或离线模式；
- 课程运行时通过 manifest 恢复 M1 `CoursePackage`、M2 `EvidenceIndexRef`、M3 `KnowledgeBundle` 及策略文件；
- 学习状态和审计数据强调不可变记录、版本与幂等。

这些边界在新架构中继续成立。

## 3. 旧主流程

### 3.1 课程知识准备

旧的主路径是：

```text
固定课程原始资料
  -> M1 按预期输入集合解析并生成 CoursePackage
  -> M2 建立证据索引
  -> M3 从 seed/结构化输入生成知识包
  -> TeacherReviewWorkflow 审核
  -> build_knowledge_bundle_after_approval 发布
  -> runtime manifest 装载
```

这个流程适合受控种子数据和开发期验收，但没有形成面向普通教师的“任意文件上传—后台解析—直接发布”产品流程。

### 3.2 学生任务

- 普通答疑：M4 路由 `qa`，主要经过 M2 检索、M7 处理和 M6 教学状态机。
- 诊断、练习、订正和阶段测评：由 M4 冻结任务计划，依次调用 M8、M2、M7、M5、M6、M9 中需要的能力。
- M4 任务计划固定课程包、证据索引和知识包引用，保证一次任务内版本一致。

### 3.3 教师复核

旧架构存在两类含义不同的“复核”：

1. M3 知识包发布审核：`draft -> submitted -> approved/rejected -> recalled`；
2. M8/M9 主观题成绩复核、重评和分析。

本次重构只取缔第 1 类知识包审核流程，第 2 类成绩复核继续保留。

## 5. 已知故障与根因快照

### 5.1 “进入知识包”返回 404

当时教师首页仍显示“知识包审核”，要求输入 `course_id`、`class_id` 和 `review_id`，并跳转至：

```text
/teacher/courses/<course_id>/classes/<class_id>/knowledge-reviews/<review_id>/
```

运行时 manifest 中存在课程包、索引和知识包引用，但数据库没有与测试数据匹配的 M3 教师审核记录。页面把“进入知识包”实现成“按审核 ID 查询”，因此已有知识包不等于一定存在可查询的审核记录，最终出现 404。

这不是单独补一条路由就能消除的产品问题；新架构删除知识包审核入口，改成按课程进入文件与解析状态页面后，该问题会随旧流程退出而消失。

### 5.2 `run_outbox_worker` 启动失败

诊断时存在两个叠加因素：

- 已有 Worker 进程运行时再次启动会争抢同一工作者/资源；
- Web 与 Worker 的旋转文件日志曾争抢文件句柄，底层错误被统一包装成 `CommandError: outbox worker could not start safely`。

把 Worker 日志拆分为 `outbox.log` 后，在旧进程停止且 Web 仍运行时执行一次性 Worker 已成功退出。这证明学习事件 outbox 本身可以工作，但错误提示和进程状态可见性不足。

新架构不会把知识解析任务塞进学习事件 outbox；它会复用 M0 的租约、心跳和幂等模式，新增独立的知识入库作业类型和命令。

### 5.3 删除固定测试文件导致导入失败

旧准备脚本和课程初始化路径隐含“预期固定文件集合”的假设。某个文件缺失、损坏或扩展名与真实容器不一致时，整个课程初始化容易失败。

真实教师场景的输入是“0 到 N 个受支持文件”，而不是“必须正好存在 5 个文件”。新架构取消文件数量假设，采用逐文件状态、部分成功和活动快照发布。

### 5.4 测试文件 5 不是合法 PPTX

PPTX 是 ZIP/Office Open XML 容器，仅使用 `.pptx` 后缀不能使任意文本成为合法演示文稿。旧测试数据曾出现扩展名正确但容器错误的问题。该问题已作为测试数据问题处理；新架构还会在入库前同时检查扩展名、MIME/魔数和容器结构，并把错误限制在该文件。

## 6. 被新架构明确取代的旧实现

以下实现只保留在 Git 历史和本快照中，不再接入活动运行时：

- 教师首页“知识包审核”表单及 knowledge-review 路由；
- M3 `TeacherReviewWorkflow` 在知识包发布中的强制门禁；
- `build_knowledge_bundle_after_approval` 作为唯一生产发布入口；
- 教师手工维护审核编号的交互；
- 以固定 seed 文件集合为生产课程导入入口；
- 单个输入文件失败即判定整批课程不可用的行为；
- 题目与知识点只能随静态知识包一次性发布的假设。

数据库中的旧审核记录可在迁移期只读保留，以便审计和回滚确认；活动代码、页面、协调器装配和权限菜单不得继续依赖它们。稳定运行并完成迁移验收后，再单独决定是否删除旧表。

## 7. 必须保留的兼容性不变量

- 仍然只有 M0–M9；重构不新增 M10。
- Django 与跨模块协调仍属于 M0。
- M1 负责确定性文件解析和来源定位，不让 LLM 替代基础解析。
- M2 继续作为统一证据检索入口，保留 PostgreSQL/pgvector 和检索审计。
- M3 继续拥有教育领域知识模型、题库、量规、蓝图和 Q 矩阵语义。
- 外部 LLM 仍只允许通过既有 DeepSeek 边界进入 M7 或 M9；知识提取、题目标注和学生答疑统一归入 M7，M9 只保留教师侧受控解读。
- M5 的 DINA/BKT、M6 的教学状态机、M8 的试卷快照、M9 的成绩复核均继续存在。
- 已发布试卷和历史学习状态引用不可被后来删除文件反向改写。
- 公开契约优先新增版本或可选字段，数据库迁移只追加，不改写已经执行的迁移。

## 8. 快照结论

旧架构的核心问题不在 M0–M9 划分，而在“知识材料如何进入 M1–M3”这一段仍是开发者导入和审核驱动。重构应保留模块边界和成熟的测评、状态、教学能力，把知识准备改造成教师可直接操作、逐文件可恢复、版本可追踪、发布可原子切换的产品流程。

## 9. 2026-08-28 被覆盖的旧评分与复核架构

本节合并记录原先分散在 M7/M9 评测、补救决策、跨模块变更和复核缺口文档中的历史事实。原文档已退出活动规范，只有本历史快照继续保留其结论：

- 填空题和带教师参考答案的主观题曾全部进入规则判分，字符串不一致会直接记 0，无法转入 DeepSeek 语义评分；
- M7 主观评分曾连续独立调用两次，M8 保留第一次分数并按两次分差决定是否复核；对应的 `double_score_disagreement_threshold`、合并函数和页面提示现已删除；
- 生产默认曾为 `all_review`，所有 M7 分数都必须人工确认；后续还存在 shadow/isotonic 选择器、离线校准与抽检设计，但未满足本次“置信度低于 0.5 才建议复核”的产品流程；
- 旧失败策略对畸形模型输出只失败关闭，没有完成“首次调用加 8 次严格格式重试—失败后 0 分/置信度 0/中文错误评语—加入建议复核”的闭环；
- 旧教师复核主要依靠 M9 队列和普通答卷入口，没有按 `(班级, attempt, paper)` 聚合的建议教师复核记录；直接 URL 也没有统一阻止非画像型答卷进入；
- `reject`、延迟入账、原作答重评、不可变审计版本和教师完整 override 的安全语义仍然有效，并被新架构保留：待复核或被驳回的分数不得提前写入 M5/M9，只有全部题目形成最终版本后才同步画像。

当前实施规范以 [`architecture.md`](architecture.md) 和 [`superpowers/specs/2026-08-28-scoring-review-redesign.md`](superpowers/specs/2026-08-28-scoring-review-redesign.md) 为准。
