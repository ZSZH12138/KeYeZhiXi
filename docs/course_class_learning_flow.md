# 课程班级学习流程（当前实现）

> 生效日期：2026-08-29
> 所有数据严格属于同一个 `(course_id, class_id)`。
> 旧架构仅作历史说明，见 [`legacy_architecture_snapshot_2026-08-25.md`](legacy_architecture_snapshot_2026-08-25.md)。

## 1. 教师准备课程

1. 教师进入指定课程、指定班级的“知识与题目”页面。
2. 教师上传课程文件和题目 TXT。文件先进入暂存区，学生此时看不到。
3. 教师在同一个课程班级下配置 DeepSeek API。密钥加密保存，不在页面、日志或接口中回显。
4. 教师点击“确定”，系统读取课程文件、抽取知识点、保存对应原文、解析题目并建立“题目—知识点”关系。
5. 全部结果通过校验后，系统一次性切换当前课程班级的活动版本。学生刷新后只会看到完整旧版本或完整新版本。

相同课程 ID 且相同班级号的教师和学生共享同一套 API、课程文件、知识点和题目关系；任一标识不同都不共享。

## 2. 学生查看课程文件

1. 系统先检查学生是否属于当前课程班级。
2. 只列出当前活动版本引用、状态为有效的课程知识文件。
3. 题目文件永远不出现在学生文件列表，也不能通过下载地址访问。
4. 教师确认删除并发布新版本后，该文件立即退出学生文件列表、下载和答疑检索。

## 3. 学生独立答疑

1. 系统检查当前课程班级是否有教师配置的 DeepSeek API；没有则显示“答疑暂不可用”，绝不回退到全局密钥。
2. 第一次 DeepSeek 调用只接收当前有效知识点的 ID、标题和别名，并返回零到多个知识点 ID。
3. 系统验证每个 ID 必须属于当前知识点白名单并去重。
4. 系统按这些知识点读取当前有效课程原文，并选取少量包含相同知识点的例题、选项及答案。
5. 课程资料完全覆盖时只按受控材料分析；部分或完全不覆盖时允许外部检索，但必须警告“无完整课程知识点支撑，建议核对事实”。
6. 页面固定输出“涉及知识点”“知识点对应原文”“分析”“相关例题”四段，外部资料另行标识。

答疑不写掌握度、做题次数、答对次数或错题账本，是完全独立的模块。

## 4. 四类试卷

所有试卷只使用教师当前发布的题目。没有可用题目时明确提示生成失败。

### 诊断测评

- 题库不少于 20 道时，随机无重复抽取 20 道；不足时使用全部题目。
- 最终评分后更新学生画像和错题账本。

### 随心练习

- 排除包含任何“未做过知识点”的题目。
- 入选概率为 `1 - 题目所涉及知识点中的最低掌握度`。
- 题量不设固定上限；本次没有随机命中时提示重试或先完成诊断。
- 只展示本次即时反馈；不进入画像测评记录、教师复核、错题账本或班级画像。

### 阶段评测

- 最多 20 道；教师题目不足 20 道时全部使用。
- 每个知识点的权重是 `1 - 掌握度`，未做过的知识点按掌握度 0 参与。
- 使用最大余数法转换整数配额。例如掌握度 `0.1/0.2/0.3/0.4` 对应 `6/5/5/4` 道。
- 某知识点题目不足时，把剩余名额按同一公式重新分给其他知识点，且不重复出题。
- 多知识点题目归到其中掌握度最低的知识点参与分配。
- 最终评分后更新学生画像和错题账本。

### 订正

- 输出当前仍有效的全部待订正错题，不限制题量。
- 已被教师从当前题库删除的错题会退出订正集合。
- 不进入学生做题记录或教师复核，也不更新画像计数。
- 满分答对后将错题状态改为已解决，下一次订正不再出现；未答对则保持待订正。
- 学生后来在诊断测评或阶段评测中再次答错同一题时，该题会重新进入订正。

## 5. 掌握度与数据库同步

每个学生、课程班级、知识点有一条权威记录：

```text
attempted_count  已计入画像的做题次数
correct_count    已计入画像的满分答对次数
attempt_status   unseen | attempted
mastery          min(0.9, correct_count / attempted_count)
```

- 没做过和做过但全错会用 `attempt_status` 区分。
- 多知识点题目会同时更新每一个涉及知识点。
- 无论规则、AI 还是教师评分，只有得到本题满分才算答对；非满分一律按错题更新画像。
- 同一次作答使用唯一投影凭证，提交重放和页面刷新不会重复累计。
- BKT、DINA、IRT 保留为影子分析能力；学生出题和页面画像使用上述权威计数。

## 6. 判分与建议复核

1. 选择题必须完全匹配正确答案才得满分，否则为 0 分。
2. 填空题和主观题完全字符串匹配时直接得满分，AI 置信度记为 1，AI 评语显示“无”，不进入建议复核。
3. 字符串不匹配时，系统把题目、标准答案、学生答案、知识点、知识点来源原文和题目满分提交给当前课程班级配置的 DeepSeek。
4. DeepSeek 返回分数、自然语言理由和置信度。格式错误时最多重试 8 次；全部失败或服务不可用时按 0 分、置信度 0 记录，并给出自然语言错误说明。
5. 置信度低于 0.5 的画像测评题进入教师“建议复核”。同一份试卷的多道待复核题合并为一条记录；练习和订正不进入该队列。
6. 教师改判时只能输入 0 到本题满分之间的分数，可附备注。确认后同步学生画像、班级快照与学生反馈；同一改判重复提交不会重复累计。

## 7. 班级快照与教师入口

- 学生人数来自当前课程班级中有效学生账号的动态扫描；每份画像测评冻结当时的班级名单规模和校验信息。
- 学生画像变化后，同步更新 M5/M9 班级快照；教师打开班级页时还会执行读时校正，避免事件投递延迟造成旧数据。
- 班级知识地图默认折叠，展示知识点名称和未做题人数，不向教师暴露内部知识点 ID。
- 班级平均掌握度只对做过该知识点的学生取平均；未做学生不参与平均与补学度计算。无人做过时，两项均显示 0。
- 补学度是“已做过且掌握度低于 0.4 的学生数 / 已做过该知识点的学生数”。未做学生不会被计入薄弱或补学人数。
- 学生个体栏只保留“查看该生掌握、错因、订正”。普通复核可按课程、班级和学生账号查找全部已完成画像测评；建议复核单独列出低置信度题目。
- “生成 AI 教学建议”只选取已有人作答且班级掌握度最低的前 10 个知识点（不足 10 个则全部），连同其课程来源原文交给当前课程班级配置的 DeepSeek。

## 8. 逐题反馈与答疑按钮

最终反馈逐题显示原题、选择题选项、涉及知识点、正确答案、有效课程原文件名、原文位置和原文。

每题的“答疑分析本题”按钮只携带一个短时有效的签名引用。服务端重新校验课程、班级、学生、试卷和题目，再从冻结试卷重建提示词，随后进入当前活动课程资料的答疑流程。浏览器不能通过修改隐藏字段读取其他学生或班级的数据；该答疑仍不会更新画像。

学生首页的“画像测评记录”只列出本人已完成的诊断测评和阶段评测，显示试卷 ID、完成时间、得分和错题数，并链接到上述逐题结果。随心练习、订正和尚未完成的答卷不出现在该列表。等待 AI 或教师完成的答卷只在等待页展示临时状态，不会更新学生或班级画像。

填空题和主观题还显示 AI 评语与教师备注。AI 评语使用普通文本展示；教师没有改判或没有填写备注时，教师备注为空。

## 9. 状态更新与删除

- 发布课程内容时，活动版本指针和内容版本号在同一数据库事务中更新。
- 更新课程班级 API 时，API 版本号同步增加。
- 学生页面每次请求都重新读取当前活动版本。
- 教师删除文件后，新活动版本不再包含其原文和题目关系；学生文件、答疑和新试卷均不能取回。
- 已发试卷继续绑定其冻结版本，保证评分和审计不被后来发布反向修改。

## 10. 从零复测

先完成迁移和全量测试，再运行：

```powershell
python manage.py reset_learning_test_state `
  --confirm RESET-LEARNING-TEST-STATE `
  --backup-dir runtime\backups
```

命令先备份 SQLite 数据库、知识上传目录、冻结答卷和订正记录，然后清空课程文件、题目、发布版本、测评记录、错题账本和学生画像。账号、角色授权、课程班级工作区以及教师的加密 DeepSeek API 配置会保留。

旧静态知识包只允许通过显式的 `COURSE_INSIGHT_ALLOW_LEGACY_TEST_BUNDLE=1` 在旧自动化测试中使用；生产流程不会回退到旧题库。
