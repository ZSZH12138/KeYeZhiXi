# 账户、课程、班级与学习流程

本文用功能层语言说明当前 MVP 的完整操作流程。

## 1. 首次启动

1. 运维人员执行数据库迁移。
2. `sync_roles --apply` 建立不可登录的管理员引导账户和权限组。
3. 运维人员为管理员设置密码。
4. Web、知识入库 Worker 和事件 Worker 分别启动。
5. 此时系统没有教师、学生、课程、班级、题库、知识点或学习记录。

## 2. 管理员登录

1. 管理员输入账户名和密码。
2. 系统确认账户类型为管理员且拥有账户管理权限。
3. 登录后只进入账户控制台。
4. 管理员看不到教师课程、班级、学生学习页或教学工具。

## 3. 创建教师或学生账户

1. 管理员选择“新增教师”或“新增学生”。
2. 输入非空账户名和非空密码；全为空格的值会被拒绝，除此之外不限制长度格式。
3. 系统生成独立的内部 `actor_id`，使用 Django 哈希保存密码。
4. 系统建立与账户类型匹配的权限组。
5. 新账户立即可以登录。

账户名必须在当前活动账户中唯一。物理注销后，系统不保存该账户名或阻止复用的指纹，因此相同账户名可以创建一个新的独立账户。

## 4. 教师创建课程班级

1. 教师输入账户名和密码。
2. 登录后进入原有课程与班级选择页。
3. 页面从数据库加载该教师实际拥有的全部活动班级，显示课程名称和班级名称。
4. 教师在“开课”区域填写课程名称和班级名称。
5. 系统创建一个独立班级容器，同时生成不可变的课程 ID 和班级 ID。
6. 新班级出现在同一页面，教师可以继续进入原有教学功能。

显示名称用于界面；内部 ID 用于 URL、授权、历史记录和幂等。教师不能看到或操作其他教师的班级。

## 5. 教师邀请学生

1. 教师进入本人班级。
2. 页面显示当前学生人数和全部学生账户名。
3. 教师在邀请框输入一个现有学生账户名。
4. 系统确认目标是活动学生账户，并确认教师拥有该班级。
5. 系统新增或恢复活动成员关系，名单版本递增。
6. 学生课程列表立即出现该班级。
7. M5/M9 班级统计按新名单修复，学生总数和各知识点未做人数随之更新。

重复邀请同一活动成员不会建立重复关系。

## 6. 教师移出学生

1. 教师从班级名单选择学生。
2. 系统再次校验教师、班级和学生关系。
3. 成员关系改为已移出，名单版本递增。
4. 学生不能再进入该班级。
5. M5/M9 快照按剩余活动成员重算，人数与未做人数更新。

移出班级不等于注销学生账户；学生在其他班级的关系和本人账户不受影响。

## 7. 教师准备教学内容

1. 教师进入班级的 DeepSeek 配置页，保存该课程班级专用密钥。
2. 教师上传一个或多个受支持的课程文件或题目文件。
3. 页面先显示待处理变更，教师确认后创建后台任务。
4. ingestion Worker 校验、解析、抽取知识点、关联题目并构建证据索引。
5. 全部发布校验通过后，系统原子切换活动发布版本。
6. 学生的新测评和答疑读取这个活动版本。

删除文件后也通过新发布版本生效。旧试卷继续绑定创建时的冻结版本，不会被后来修改。

## 8. 学生进入课程

1. 学生输入账户名和密码。
2. 系统只列出该学生当前活动成员关系对应的课程班级。
3. 学生点击课程名称和班级名称进入学习页。
4. 学生不能手工填写任意课程 ID 或班级 ID 绕过成员校验。

学生没有创建、注销、开课、邀请或移出成员的入口和权限。

## 9. 学生测评

学生选择一种任务：

- 诊断测评：生成用于建立或更新画像的试卷；
- 随心练习：进行即时练习，不计入画像历史；
- 阶段评测：按当前薄弱知识点生成试卷并更新画像；
- 错题订正：只处理当前错题，不计入画像历史。

开始任务时，M4 冻结任务范围和活动知识版本，M8 冻结试卷、题目、参考答案与量规。提交后：

1. 选择题按参考答案精确评分。
2. 填空题和主观题先做精确匹配；不匹配时才进入 DeepSeek 语义评分。
3. 低置信度或模型失败题进入教师建议复核。
4. 已完成的诊断和阶段评测更新 M5 学生画像与班级统计，并进入学生历史。
5. 随心练习和订正只完成当前操作，不进入画像测评历史。

## 10. 结果、答疑与复核

学生结果页按题展示原题、选择项、答案、得分、知识点、来源文件和课程原文。逐题“答疑分析本题”只提交短时签名引用；服务端重新构造题目内容并校验作用域。

教师可以：

- 按课程、班级和学生账户查看已完成的画像测评；
- 查看按试卷聚合的低置信度建议复核；
- 为单题填写合法分值和可选备注；
- 生成基于班级薄弱知识点与课程原文的教学建议。

改判会形成新的评分审计版本，并幂等同步学生反馈、个人画像和班级快照。

## 11. 注销学生

1. 管理员选择学生账户并查看影响范围。
2. 管理员再次完整输入目标账户名确认。
3. 系统在一个事务中删除学生的会话、成员关系、作答、评分、反馈、错题、画像和分析投影。
4. 系统删除学生用户行。
5. 受影响班级递增名单版本并刷新统计。

成功后系统中没有该账户身份。相同账户名可以重新创建，但新账户会获得新的内部 `actor_id`，不会继承旧数据。

## 12. 注销教师

1. 管理员选择教师账户并查看其拥有的班级数量。
2. 管理员再次完整输入目标账户名确认。
3. 系统对教师拥有的每个课程班级删除成员关系、授权、课程文件、题库、知识点、发布版本、DeepSeek 配置和全部学习数据。
4. 系统删除班级容器和教师用户行。
5. 数据库提交后，待办清理器删除对应上传文件和冻结答卷。

如果数据库清除失败，整个事务回滚；如果事务后的文件删除暂时失败，待办记录保留并由 `cleanup_erasure_files` 重试。管理员页面不会把未完成清理显示为成功。

## 13. 管理员边界

管理员不会因为可以注销教师而获得教师权限。管理员不能进入班级、查看学生作答、修改题库、配置 DeepSeek 或生成教学分析；所有此类请求都会由服务端拒绝。
