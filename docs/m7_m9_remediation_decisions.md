# M7/M9 修复决策与安全边界

状态：负责人已于 2026-08-06 确认，供实现和全局代码审核使用。

本文记录 `M7_M9_问题清单与修改建议.md` 后续修复所依赖的产品决定、
上线约束和暂不纳入当前范围的安全能力。实现若偏离本文，必须在变更说明中
明确原因并重新确认。

## 1. 学生证据引用

- 当前学生页面暂时不显示证据原文。
- 学生端只显示证据来源和定位信息，例如 `source_id` 与 `locator`。
- 不允许把 `EvidenceChunk.text` 原样写入任何学生可见字段。
- 后续如恢复证据摘录，只能使用经过明确学生可见性分类和答案泄露检查的短摘录；
  该能力不属于本轮最低修复范围。
- 学生可见安全门必须覆盖反馈正文、量规反馈、学生证据字段和引用字段，不能只
  检查主消息。

对应问题：M7-01。

## 2. `reject` 教师复核语义

`reject` 采用“拒绝本次评分，等待重评”的语义：

- 保存教师决定、教师意见和审计身份；
- 本次评分不得成为可用最终成绩；
- 不得使用被拒绝的分数更新 M5 学习者/班级状态；
- 不得把被拒绝的分数计入 M9 分数统计或最近成绩；
- 后续必须产生新的评分，或者由教师提交完整、守恒的 `override` 后才能继续；
- 当前代码只有完整 `override` 可达，真正 rescore 的身份、版本、权限、幂等、恢复及
  反馈重建协议必须由全局审核冻结后另行实现；在此之前不得宣称“等待重评”已闭环；
- `reject` 不得自动把学生分数改为零分。

实现必须让 M9 保存、M8 应用边界、应用工作流、M5 状态更新和 M9 报表使用同一
语义，不能只修复 `final_total_score` 的局部校验。

对应问题：M9-02。

## 3. 真实 DeepSeek 学生评分与个人信息治理

项目近期计划启用真实 DeepSeek 学生评分，但启用条件是个人信息出站治理先完成并
保持失败关闭：

- 邮箱、手机号、身份证号、学号等普通直接标识符采用确定性自动脱敏；
- 姓名、详细地址、健康、家庭等自由文本由本地 Presidio/spaCy 与经审批、校验和
  钉住的轻量语义分类器复核，不再依赖不断补充的自由文本关键词；
- 脱敏导致答案失去主要评分语义时阻断，不得发送残缺答案进行评分；
- 未识别、置信不足、依赖/工件缺失、治理失败或策略版本不可用时阻断；
- 审计只保存治理结果、策略/复核器指纹、校验和和安全标记，不保存命中的个人信息原文；
- 不提供默认开启的绕过路径。未来若增加例外授权，必须单独设计权限、时限和审计。

在这些条件满足前，真实学生答案出站必须保持关闭。

对应问题：M7-03。

## 4. 模型调用审计

- 模型调用审计保留 180 天；保留期限应通过受控配置表达，不在业务代码中散落
  魔法数字。
- 仅管理员可以读取调用审计，教师和学生不能读取。
- 允许保存调用 ID、请求 ID、模型/策略/提示版本、token、延迟、状态、错误码、
  安全标记、证据 ID 和输入输出校验和。
- 不得保存完整提示词、学生答案、命中的个人信息或原始 provider 响应。
- 持久化必须原子、幂等，并在 SQLite、PostgreSQL 和 SQLite 到 PostgreSQL 迁移中
  保持等价。

对应问题：M7-04。

## 5. M9 来源报告 checksum 的当前目标

当前安全目标是防止程序错误、报告误关联和迁移损坏：

- 模型审计必须把 `source_report_id` 与权威报告 checksum 强绑定；
- 保存、读回和 SQLite 到 PostgreSQL 迁移时都必须执行同一跨记录校验；
- checksum 仍使用项目统一的规范化 JSON SHA-256 规则。

### 明确的非目标与剩余风险

上述方案不是抗恶意篡改机制。拥有足够数据库写权限的主体可以同时修改权威报告、
模型审计及其 checksum，并重新计算普通 SHA-256。仅增加独立 checksum 列或跨表比较
不能抵抗这种情况。

> **全局审核 Codex 注意：** 请在审核实现时复核该威胁边界，并明确建议项目是否
> 需要升级为密钥与数据库分离的 HMAC/数字签名、外部追加式审计日志或不可变存储。
> 当前负责人尚未确认未来是否存在合规取证或对抗数据库高权限写入者的需求，因此
> 当前实现范围只包含一致性与迁移完整性，不应宣称具备防篡改取证能力。如果审核
> 认为现有业务风险已经要求更强机制，请将其作为显式阻断意见提出，而不是静默扩大
> 本轮实现范围。

对应问题：M9-04。

## 6. 暂缓事项

M9-05 继续依赖 M8 真实 shadow 标定。在 M8 尚未产生真实样本、指标和版本绑定前，
`ModelQualityReport.status="insufficient_data"` 是预期的失败关闭行为。最低样本量、
拟合质量、稳定性、公平性及发布阈值待 M8 能力就绪后另行确认。

## 7. 审核验收要点

全局审核至少应确认：

1. 学生页面和学生 API 中不存在未经审查的证据原文；
2. M7/M9 侧不会把 rejected 评分重新包装成零分或权威个人报告；B-05 的 M5/M6
   延迟入账与 rescore 闭环必须按合并必读文档由公共编排负责人完成；
3. 真实 DeepSeek 调用不可能绕过出站治理组件；
4. 审计保留字段符合白名单且只有管理员可读；
5. SQLite、PostgreSQL、迁移和读回执行等价的 checksum 关联校验；
6. 文档和实现没有把普通 SHA-256 一致性校验描述为抗恶意篡改能力。
